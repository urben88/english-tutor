# Project analysis

## Detected stack

| Area | Finding |
|---|---|
| Backend | Python (uv, `pyproject.toml`), FastAPI-style API in `backend/api`, STT/LLM/TTS adapters |
| Frontend | React 19 + Vite 8 + TypeScript 7 SPA in `frontend/` (npm, `package-lock.json`) |
| Tests | Vitest + Testing Library (frontend), pytest (backend) |
| Structure | Atomic design (`components/atoms`, `molecules`, `organisms`), hooks as containers, `audio/` for mic/player |
| Rendering | DOM only. No canvas or WebGL code |
| App type | Client-side SPA served on port 8765 (`Iniciar.cmd`) |

## Existing 3D dependencies

None. `three`, `@react-three/fiber`, `three-vrm` and Babylon.js are all absent.

## Recommended runtime

**Plain `three` (one dependency), wrapped in a small React component.** We are not using React Three Fiber + drei.

The assistant is a single self-contained canvas, not a scene composed from React. One package keeps the bundle and the upgrade surface small. The module is framework-agnostic, and `src/react.tsx` adapts it to React.

## Recommended asset format

`.glb` with a skeleton and morph targets. See `CHARACTER-OR-ASSET-SPEC.md` for why `.vrm` is not exported yet.

## Workflow comparison

| Workflow | Likeness | Rig + face | Free tools here | Verdict |
|---|---|---|---|---|
| Image-to-3D (TripoSR etc.) | Medium for one clean photo; poor for a 12-panel cartoon sheet. Glasses and hair break | None: no skeleton, no blend shapes. Everything has to be added by hand | Needs a Python/PyTorch install | Rejected for an animated face |
| Reference-guided procedural (Blender script) | Stylized and recognizable (hair, glasses, shirt, eye colour), not a portrait | Built in: bones + 20 shape keys generated by code | Blender 5.2 is already installed | **Chosen**: reproducible, editable, runs headless |
| VRM humanoid (VRoid Studio → `.vrm`) | Best for this anime/cartoon style | Built in: VRM expressions (`aa ih ou ee oh`, `blink`, `happy`…) | VRoid Studio is not installed; GUI work | Recommended upgrade path |

## Are facial rigging, blend shapes and visemes needed?

- **To move the mouth: yes, some deformation is needed.** A facial bone rig is not needed for a stylized face. Blend shapes (morph targets) are enough and cheaper.
- **Visemes:** the TTS adapter (`backend/adapters/tts/supertonic*.py`) returns audio without phoneme timings. True phoneme-accurate visemes are therefore impossible today. The runtime picks visemes from the loudness and brightness of the audio. That reads as speech, but it is not exact lip-reading. The 7 viseme shapes are still worth having, because they make the mouth look like it forms sounds instead of flapping.
- **Blink and expressions** are blend shapes too (`blink_L/R`, `eyeWide`, `eyeSquint`, brows, mouth shapes).

## Integration point

`frontend/src/App.tsx` (container component) already knows `tutor.speaking`, `tutor.busy` and the voice-mode state. The assistant mounts there as one extra presentational element.

## Risks and constraints

- `three` is a new dependency. It needs your approval. Bundle cost has not been measured; roughly 150–200 kB gzip is typical for the renderer plus GLTFLoader.
- `player.ts` creates its `Audio` element internally. Audio-driven lip-sync needs that element exposed (small diff in `INTEGRATION.md`). Without it, the mouth moves procedurally while `tutor.speaking` is true.
- WebGL can be unavailable (old GPUs, some VMs). The component then fails silently and the app keeps working.

## Files that may need modification (only with your approval)

- `frontend/package.json`: add `three` (+ `@types/three` dev).
- `frontend/src/App.tsx`: mount the component.
- `frontend/src/audio/player.ts`: optional hook to expose the audio element.
- `frontend/vite.config.ts` / `tsconfig.json`: only if you import directly from `3d/` (outside `src`). The alternative is copying `src/` into the frontend.
